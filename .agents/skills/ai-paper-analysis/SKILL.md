# AI 论文精读与评估

按论文逐篇分析 AI 模型及其实验证据。用户可提供研究主题、题名、DOI、网页链接或本地 PDF；默认在对话中交付分析和 Mermaid 架构图。不要仅凭摘要补全论文未披露的方法或数值。

## 确认论文与证据

1. 有明确论文时，先核对题名、作者、年份、DOI 和版本，优先阅读用户提供的正文及补充材料；只有研究主题时，先检索并筛选相关原始研究，再逐篇分析。检索遵守项目规则：排除 MDPI 旗下期刊论文；用户未明确要求综述时排除综述、系统综述和元分析。用户明确指定的论文即使属于这些类别，也照常分析并标明例外。
2. 优先核对论文正文、附录、数据与代码声明、数据集官方页面及可访问的仓库。引用关键结论时标明论文页码、章节、图表或可核验链接。区分“论文报告”“独立核查”和“推断”；来源互相矛盾时指出差异。
3. 正文无法获取时，先用可核验的公开材料完成能够支持的部分，并明确哪些分析受限；需要正文或本地文件才能判断的事项请用户提供。此 Skill 不自动启动 DOI Harvester、不创建文献目录或 Excel 汇总。用户另行要求下载时，转用 `autopaper-literature` 并遵守其确认流程。

## 核心创新点优先

确认论文身份后，先提炼并在回答开头给出核心创新点，再展开数据、架构和实验分析。按论文实际内容区分新结构、新方法、新机理或其他创新；每点用简短文字说明相对已有方法改变了什么、解决什么问题，并附正文或图表依据。只有作者提出的机理假说时标为“假说”，没有充分对照或实验支持时标明证据不足；不要把常规组件组合、性能提升或作者的宣传措辞直接认定为原创创新。无法取得正文时只报告公开材料能够支持的创新点，并注明待核实。

## 数据集与划分

1. 查明论文是否提供数据集、数据可用性声明、下载入口、许可和访问条件。给出论文指明且已核验的入口，供用户自行保存到本地；不把代码仓库或补充材料误称为完整数据集。论文没有可审查的数据集时注明原因，跳过数据文件与划分审查。
2. 论文描述了数据集、但本地数据尚未提供时，先依据论文说明记录样本数、来源、训练/验证/测试比例或数量、划分单位和方法，评估重复样本、相似或关联样本跨集合、时间或主体泄漏、分布偏移、标签质量、代表性与任务匹配程度。此时明确写“未检查原始数据”，不要把论文声明写成实测结果。
3. 用户提供本地数据路径后，在不改动数据的前提下核查实际文件和划分：样本数与标签分布、重复或近重复、主体/时间/来源重叠、预处理是否只在训练集拟合，以及训练、验证和测试集的相关性及合理性。大规模或受限数据可抽样核查，但须说明覆盖范围；不要执行数据集附带的不可信代码。数据不足以核实时标为未知。

## 模型、输入与创新

1. 梳理每个输入的来源、字段或模态、张量形状或数据结构、预处理、特征构造、标签和监督信号，说明输入如何组合、进入哪些模块，以及训练与推理是否不同。缺失的维度或处理步骤不得猜测。
2. 从论文架构图、方法和附录重建 Mermaid 流程图，覆盖输入、主要模块、融合或连接、输出与损失；标清论文未明确给出的推断连接。图旁说明关键维度和数据流，避免把示意图误称为作者原图。
3. 指出论文实际使用的 baseline、相对 baseline 新增或修改的模块、作者声称解决的问题，以及消融实验能否支持各模块的作用。无可比 baseline 或消融时直接说明证据不足。

## 结果与可信度

1. 按数据集、划分和评价条件整理适用指标，包括论文报告的 R²、MSE、RMSE、MAE 或分类指标；注明单位、方向和结果来自训练集、验证集还是测试集。比较同条件 baseline 时给出原值、新值、绝对差与相对变化；基线为零或条件不一致时不计算相对提升或跨条件结论。
2. 对“提升了什么、提升了多少”分别使用主结果和消融结果作证，区分作者报告与自行重算。不得把训练集分数当作泛化能力，也不得由图形目测捏造精确数值。
3. 结合样本量、独立测试或外部验证、重复运行、随机种子、误差条/置信区间、统计检验、数据泄漏风险及代码数据可用性，给出有依据的定性可信度判断。没有原始预测、重复实验或必要统计量时，不编造置信区间或确定性百分比。
4. 分析模型优势、局限与适用边界，并将改进建议对应到已识别的薄弱环节，例如划分方式、外部验证、消融、校准、鲁棒性、效率或输入特征。最后给出一段综合评价，说明结论能支持到什么程度。

## 交付格式

回答首先列出“核心创新点”，按新结构、新方法、新机理等实际适用类别概括，随后按“论文身份与证据 → 数据集及划分 → 输入与架构图 → baseline 与消融证据 → 指标与提升 → 可信度、优劣和改进 → 总结评价”组织。没有数据集或缺少材料时保留相应状态说明，不用虚构内容填满栏目。若用户指定报告格式、研究重点或比较多篇论文的方式，以用户要求为准。
